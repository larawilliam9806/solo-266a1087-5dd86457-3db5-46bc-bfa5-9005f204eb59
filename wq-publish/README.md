# 水质实验室 · 批次修订发布台

供水质实验室数据员使用的批次修订发布页（Flask + SQLite）。浏览器上传仪器导出的
CSV、填写批次号，系统逐行校验后预览**新增 / 修改 / 撤回（删除）**差异，确认后
**整批替换**下游采集程序读取的本地 CSV，并在网页登记当前版本与行数。

## 功能与规则

- 上传 CSV 必须包含三列（表头兼容中英文）：`样本号`、`检测项目`、`浓度(mg/L)`
  （亦接受 `sample_no / analyte / concentration` 等常见别名，UTF-8、支持 BOM）。
- 逐行业务校验，错误带行号提示：
  - 同一样本同一检测项目不得重复；
  - 浓度必须是数字且 **≥ 0**（拒绝负数、空值、NaN、Inf、非数字）；
  - 样本号、检测项目不能为空，列数必须与表头一致。
- 上传内容代表修订后的**完整一批**：当前版本中存在、但本次 CSV 未包含的行，
  在预览中列为「撤回（删除）」，确认后该检测结果即被撤回。
- 预览页分类展示新增、修改（旧值→新值）、撤回、不变四类差异，确认后才发布。
- 首页登记当前版本号、批次号、行数、发布时间（UTC）与内容 SHA256，并提供
  已发布 CSV 的在线查看入口和事件日志（含每次恢复记录）。

## 双文件合并（两台仪器各导出同一批次的部分结果）

浏览器进入「双文件合并」页（`/merge`），填写批次号并同时选择仪器 A、B 的 CSV：

- 两个文件各自沿用上面的原有列校验；**任一份文件内出现重复的
  （样本号, 检测项目）即整份拒绝**，两份都不会进入预览。
- 仅一份出现的结果直接采用（来源记为该仪器）；两份都有且浓度相同则合为一行，
  来源记为「双份一致」；浓度不同为冲突项。
- 冲突项必须**逐项选择采用仪器 A 或仪器 B，并填写理由**；可以把已选部分组成
  保存后再继续，但未全部选完、未填理由时发布按钮禁用且服务端同样拒绝。
- 确认后**整批发布**：每个（样本号, 检测项目）只留一行，与单文件修订一样原子
  替换 `downstream/published_results.csv`，版本号延续同一登记序列。
- 新版本保存**逐行来源**（仅 A / 仅 B / 双份一致 / 冲突选定）、双份原始浓度与
  冲突理由；「合并版本核对」页（`/merge/versions`）可按版本逐行核对，重启后
  仍可查阅。
- 若在确认前当前版本已被其他页面发布改变，该合并会话立即作废，**此前保存的
  来源选择与理由全部清空失效**，必须重新上传两个文件预览。
- 发布失败（下游写盘失败或写库失败）不会留下文件、登记或逐行来源中的任何
  部分更新：数据库事务回滚且正式文件恢复为发布前内容，会话仍可用于重试。

## 本地启动

环境要求：Python 3.10+（依赖 Flask，生产建议 waitress）。

```bash
cd wq-publish
./run.sh                 # 自动创建 .venv、安装 flask，监听 http://127.0.0.1:5000
```

Docker Compose：

```bash
cd wq-publish
docker compose up -d --build     # 监听 http://127.0.0.1:5000
# 数据与下游目录分别挂载到宿主机 ./data、./downstream
```

容器使用 `waitress-serve --call ... wsgi:create_app` 单进程多线程运行，
`data/`（SQLite 登记、密钥、隔离区）与 `downstream/`（正式 CSV）需要持久化卷。

手动方式：

```bash
python3 -m venv --without-pip .venv   # 若系统带 ensurepip，直接 python3 -m venv .venv
# 按你的环境引导 pip 后：
.venv/bin/pip install -r requirements.txt
WQ_DATA_DIR=$PWD/data WQ_DOWNSTREAM_DIR=$PWD/downstream \
  .venv/bin/waitress-serve --call --host=127.0.0.1 --port=5000 wsgi:create_app
```

环境变量（可选）：

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `WQ_DATA_DIR` | `./data` | SQLite 数据库、flask 密钥、隔离区存放目录 |
| `WQ_DOWNSTREAM_DIR` | `./downstream` | 下游采集程序读取目录，正式文件固定名为 `published_results.csv` |

下游采集程序只需固定读取 `WQ_DOWNSTREAM_DIR/published_results.csv`。

## 操作流程

1. 打开首页，填写批次号并选择仪器导出的 CSV，点击「校验并预览增删改」。
2. 校验失败：回到首页逐条显示带行号的错误，修正后重新上传，不产生任何数据变更。
3. 校验通过：进入预览页核对新增/修改/撤回差异，可「放弃本次修订」或
   「确认无误，整批替换并发布」。
4. 发布成功后回到首页，登记版本号递增、行数更新，下游文件已原子替换。

双文件合并流程：

1. 打开「双文件合并」页，填写批次号，同时选择仪器 A、B 的 CSV 并生成合并预览。
2. 校验失败：逐文件显示错误，任一份整份拒绝，不产生任何数据变更。
3. 预览页查看仅 A / 仅 B / 双份一致 / 冲突四类；对冲突项逐项选择来源、填写理由，
   可「保存已选项」，全部选完后发布按钮可用。
4. 发布成功后跳转到合并版本列表，可逐版本核对该批每一行的来源、双份原值与理由。

## 数据一致性设计（如何保证要求）

**下游只会读到完整旧版或新版**

- 发布时先把新 CSV 写入下游目录内的同目录临时文件（`.tmp-publish-*.csv`），
  `flush + fsync` 后调用 `os.replace` 原子改名覆盖正式文件，并 fsync 目录。
  改名瞬间下游要么看到旧文件、要么看到完整新文件，不会读到半写内容；
  临时文件以 `.` 开头且与正式文件名不同，不会被按固定文件名读取的采集程序读到。

**文件与登记的事务关系、崩溃自动恢复**

- SQLite（`data/wq_publish.db`）是版本登记与全版本结果的唯一真相源，
  发布在 `BEGIN IMMEDIATE` 事务内完成「原子换文件 → 写新版本结果 → 更新登记表」。
- 每次启动（`Storage.recover()`）自动核对并修复：
  1. 清理崩溃遗留的 `.tmp-publish-*` 临时文件；
  2. 正式文件缺失或 SHA256 与登记不符时，以数据库登记为准原子重建；
  3. 「文件已改名但事务未提交」的现场，重启后回滚为登记中的完整版本；
  4. 下游目录中未登记的游离文件移入 `data/quarantine/` 隔离（不直接删除）；
  5. 超过 24 小时未确认的预览会话自动作废。
  所有恢复动作写入 `event_log` 并展示在首页。

**两个页面从同一版本发起修订，只允许一个成功**

- 每次预览生成带随机 token 的修订会话，记录发起时的基线版本 `base_version`。
- 确认发布时在写事务内重新比对当前版本：基线已被其他发布超越时，本会话
  标记为 `obsolete` 并返回 409 过期预览页（仍展示旧基线差异供核对），
  明确要求重新预览，绝不可能覆盖先发布者；重新预览后即可正常发布。
- 同一会话重复发布、已取消/已发布/已过期会话再次确认，一律拒绝。

**合并批次的失败与过期语义**

- 合并会话同样记录 `base_version`。确认发布或「保存已选项」前重新比对当前版本；
  已被超越时会话标记 `obsolete`，已保存的来源选择与理由全部清空（返回 409），
  必须重新上传两个文件。
- 发布在一个 `BEGIN IMMEDIATE` 事务内完成。顺序为：锁定并复核会话与基线 →
  校验所有冲突项均已裁决 → 原子换文件 → 写结果行、逐行来源、登记与会话状态 →
  提交。写库任一步失败都会回滚事务，并把正式文件恢复为发布前的字节内容，
  因此不会留下文件、登记或来源记录的部分更新。
- 若进程在「文件已改名、事务未提交」之间崩溃，重启 `recover()` 以数据库登记
  为准重建正式文件，撤下未登记的版本；已发布版本的逐行来源保存在
  `merge_sources` 表中，重启后仍可核对。

## 部署提示与已知限制

- `waitress-serve --call --host 127.0.0.1 --port 5000 wsgi:create_app` 为推荐
  运行方式（Docker 镜像即采用它），`flask run` 仅用于本地开发。并发正确性依赖
  SQLite 的 `BEGIN IMMEDIATE` 文件锁与同目录 `os.replace`，多 worker/多容器部署
  时必须共享同一个 `WQ_DATA_DIR` 与 `WQ_DOWNSTREAM_DIR`（且两者需为本地文件系统，
  不支持跨主机挂载）。
- 全量结果按版本保留在 `results` 表中，合并批次的逐行来源保留在 `merge_sources`
  表中；当前未提供历史版本回滚的页面入口（数据具备，可后续增加）；历史 CSV
  文件本身只保留最新一版。
- 上传上限 16MB（每个文件）；认证、权限控制未包含在本版本内，建议仅监听内网或
  前置反向代理加访问控制。
